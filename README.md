## 1. 왜 이걸 만들었나

어릴 때 『리틀 브라더』와 『홈랜드』를 읽은 것이 자아 형성에 큰 영향을 줬고, 그 서문을 통해 애런 슈워츠를 알게 됐다. 지금 네트워크 보안과 검열 저항 쪽을 공부하게 된 출발점이 그 책들이다. 닥터로우는 저작권과 정보 접근에 대한 주장을 글로만 하지 않고 자기 책을 실제로 무료 공개하는 방식으로 실천해왔고, 이 번역이 가능한 것 자체가 그 실천의 결과다. 국내에 번역되지 않은 그의 다른 작품을 읽고 싶었다는 것이 이 프로젝트의 직접적인 이유다.

## 2. 무엇인가

코리 닥터로우의 『Makers』(2009)를 한국어로 옮기는 번역 파이프라인이다. 번역문 자체는 이 저장소에 없고 스크립트와 번역 방침만 있다. 원문이 CC BY-NC-SA 3.0으로 공개되어 개인 번역과 배포가 허용된다.

이 저장소는 다음 구조를 중심으로 동작한다.

- `translate.py`: 원문 조각을 번역 API로 보내고, `out/`에 각 조각을 개별 파일로 저장한다.
- `merge.py`: `out/`의 결과를 번호순으로 이어붙여 `makers-ko.md`를 만든다.
- `makers-script.md`: 이 프로젝트의 동작 명세와 프롬프트 구성을 정리한 문서다.
- `방침.md`: 인물별 말투, 용어, 경어 체계, 번역 판단 기록을 정리한 규칙집이다.
- `chunks/`: 원문 조각 파일이 들어가는 입력 폴더다.

## 3. 원서 준비

`craphound.com/makers/`에서 plain text로 받아 조각내어 `chunks/`에 배치한다. 파일명은 001.txt처럼 세 자리 번호를 붙여 관리한다. 이 책의 경우 48개 조각이 나왔다.

이 프로젝트는 원문을 단일 파일로 넣지 않고, 조각 단위로 번역을 수행한다. 큰 문서를 한 번에 보내면 토큰 한도로 잘릴 수 있고, 문맥 유지도 떨어지기 때문에 고정된 번호 단위로 나누는 방식이 기본이다.

## 4. 조각 나누기

`$$$$`로 PART 분할, `#`로 장면 분할, 3,000~5,000단어로 묶되 장면 경계를 넘지 않게 한다. 장면 중간에서 끊으면 문맥이 끊겨 호칭과 어조가 튄다.

이 방식으로 번역할 때는 각 조각이 자기 완결성보다 이전 문맥과 연결되는 흐름을 유지하는 것이 중요하다. 그래서 전 단계 번역 결과의 마지막 2~3문단을 다음 프롬프트의 문맥으로 넣는 구조를 갖추고 있다.

## 5. 방침 파일

매 요청에 전문을 넣는다. 한국어에는 원문에 없는 경어 층위가 있어, 인물 관계마다 기준을 미리 정해두지 않으면 조각마다 달라진다. 용어·말투·판단 기록을 누적한다.

`방침.md`는 단순한 가이드가 아니라 번역 파이프라인의 핵심 입력이다. 여기에는 다음 내용을 넣어둔다.

- 인물별 말투와 경어 표준
- 확정 용어와 미확정 용어 목록
- 이전 사건 참조 기준
- 번역 판단 기록

이 규칙집을 매번 API 요청 본문에 넣어, 조각마다 어조가 흔들리지 않도록 한다.

## 6. 직전 문맥

직전 조각의 번역 결과 마지막 2~3문단을 함께 넣는다. 원문이 아니라 번역문이어야 어미가 이어진다.

이 구조는 단순히 문장을 이어 가는 것이 아니라, 인물의 말투와 공적/사적 관계를 유지하기 위해서 중요하다. 원문 문맥만 보면 장면 경계의 어조가 어색해지기 쉬운데, 이전 번역문을 참조하면 한국어 문법과 어미 선택이 자연스럽게 이어진다.

## 7. 겪은 문제

이번 프로젝트를 진행하면서 몇 가지 실제 문제가 있었다.

- `max_tokens` 12000에서 잘림. 한국어는 영어보다 토큰이 많이 들어 32000으로 상향했다.
- `max_tokens`를 올리자 Anthropic SDK가 스트리밍 호출을 요구했다.
- 스트림 이벤트와 `get_final_message()`에서 텍스트를 이중 수집해 결과가 두 배로 나오는 문제가 있었다.
- 출력 버퍼링 때문에 로그가 안 찍혀 `python -u`가 필요했다.


## 8. 사용법

이 저장소는 `.env`에 `ANTHROPIC_API_KEY`를 넣고 실행하는 구조를 기준으로 한다.

예시:

```bash
python translate.py --dry-run
python translate.py --range 10-20
python translate.py --only 12
python merge.py
```

실제 동작은 다음과 같다.

- `--dry-run`: API 호출 없이 어떤 조각이 처리될지 출력한다.
- `--range 10-20`: 지정 범위만 처리한다.
- `--only 12`: 특정 조각 하나만 재처리한다. 기존 파일이 있어도 덮어쓴다.
- 이어쓰기 동작: 이미 완료된 조각은 건너뛰고, 중단 후 재실행 시 남은 조각만 이어서 처리한다.
- 실패해도 전체 실행을 중단하지 않는다. 실패한 조각 번호는 `failed.log`에 남기고 다음 조각으로 진행한다.
- 각 요청 사이에는 3초 간격을 둔다.
- 시작 시 전체 조각 수와 이미 완료된 수를 출력하고, 종료 시 처리한 조각 수, 건너뛴 수, 실패한 수, 총 소요 시간을 요약한다.

로그가 버퍼링되는 환경에서는 `python -u`로 실행하면 실시간 진행 상황을 더 잘 볼 수 있다.

## 9. 라이선스

코드는 MIT 라이선스를 적용한다. 이 파이프라인으로 생성되는 번역문은 원문의 CC BY-NC-SA 3.0을 승계한다.

즉, 소스 코드와 번역 결과물의 라이선스는 서로 다르며, 번역문은 원문 기반 작업이므로 원문의 배포 조건을 유지한다. 이 저장소에서는 원문 자체를 그대로 올리지 않고, 원문에 대한 변환 작업과 번역 절차를 코드와 문서로 남기는 방식을 택한다.
